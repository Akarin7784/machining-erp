# 05 权限矩阵

实现位置：`db/migrations/20261020000006_rules_security_views.sql`。测试：`db/tests/t00_guards.sql`。

## 1. 多租户（行级）

- 所有带 `tenant_id` 的表启用 RLS，策略 `tenant_isolation`：`USING (tenant_id = app_tid()) WITH CHECK (tenant_id = app_tid())`。
- 所有 RLS 表均 `FORCE ROW LEVEL SECURITY`，表所有者为非超级用户 `erp_owner`，所有者同样受租户策略约束（t06）。
- 应用连接池在每个会话设置 `SET app.tenant_id = '<uuid>'`、`SET app.user = '<登录名>'`。
- `tenant_id` 默认值为 `app_tid()`，插入时无需传。
- 行情参数 `ref_param` / `reference_source` 为全局表，不分租户。
- 视图均为 `security_invoker`，查询视图时同样受 RLS 与列权限约束。

## 3. 写操作限制

- 所有业务角色对流水表（库存、应收应付、凭证、报工、成本、委外流水、审计）**没有 UPDATE/DELETE 权限**；即使超级用户执行，也会被 `trg_append_only` 拒绝。
- 低毛利报价审批 `fn_quote_decide` 仅 `erp_manager` 成员或超级用户可调用。
- 报工、退货联动等需要写入成本/总账的触发器为 `SECURITY DEFINER`，操作工报工时成本自动入账，但操作工本人读不到成本表。
- 审计：业务表都挂 `trg_audit`，记录前后镜像、操作人（`app.user`）和时间。
